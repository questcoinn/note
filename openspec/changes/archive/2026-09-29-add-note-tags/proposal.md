## Why

목업을 걷어낸 변경(`add-note-create-delete`)에서 태그 칩과 사이드바 태그 목록도 함께 사라졌다. 저장 형식에는 `tagIds` 자리만 남았고, 태그를 붙이거나 태그로 노트를 모아 볼 방법이 없다. 폴더가 노트를 나눠 담는 분류 축을 맡고 있으니, 태그는 노트 사이를 잇는 꼬리표로 되살린다. 노트를 보다가 같은 꼬리표가 붙은 다른 노트로 바로 건너갈 수 있게 한다.

## What Changes

- 에디터 상단 줄 아래에 태그 줄을 둔다. "태그" 라벨, 붙은 태그 칩(떼기 버튼 포함), 항상 보이는 태그 입력창이 있다. 입력창에서 Enter를 누르면 태그가 붙고, 이미 쓰고 있는 태그는 입력창의 제안 목록(`<datalist>`)으로 고를 수 있다.
- 태그 이름은 앞뒤 공백과 맨 앞의 `#`을 지운 값이다. 이름 안의 공백은 허용하고, 최대 길이는 정하지 않는다. 다른 노트에 대소문자만 다른 같은 태그가 있으면 그 철자를 따른다. 같은 노트에 이미 있는 태그와 빈 이름은 무시한다.
- 태그를 붙이거나 떼면 바로 저장하고 노트의 수정 시각은 바꾸지 않는다(폴더 바꾸기와 같은 방식).
- 태그는 따로 저장하는 개체가 아니다. 어떤 노트에 붙어 있을 때만 존재하고, 마지막 노트에서 떼면 사라진다.
- 노트 카드에 태그 칩을 붙인 순서대로 다시 보여준다. 칩을 누르면 목록 범위가 그 태그로 바뀐다. 목록 제목은 `#태그`이고, 그 태그가 붙은 노트만 보인다. 지금 보고 있는 태그의 칩은 selected로 보인다.
- 태그 범위는 "전체 노트", "폴더 없음", 폴더와 나란한 범위다. 태그 범위를 보는 동안에는 사이드바에 active 항목이 없다. 나가기 버튼은 두지 않고, 사이드바 항목을 눌러 다른 범위로 간다.
- 태그 범위에서 만든 새 노트에는 그 태그가 붙고, 폴더는 "폴더 없음"이다.
- 보고 있는 태그를 쓰는 노트가 모두 없어지면(태그 떼기, 노트 삭제 등) 범위는 그대로 두고 태그가 붙은 노트가 없다는 빈 상태를 보여준다.
- 사이드바에는 태그 목록을 두지 않는다(지금 제약 유지).
- **BREAKING**(저장 형식): 노트 레코드의 `tagIds` 필드를 태그 이름 배열 `tags`로 바꾼다. 저장 형식 버전(v1)은 올리지 않는다. 배포된 적이 없어 이관 대상 브라우저가 없다고 본다. `tags`가 없는 기존 레코드는 손상된 레코드 규칙에 따라 건너뛴다.
- **BREAKING**(화면): "노트 카드는 태그 칩을 표시하지 않는다" 제약과 "새 노트는 태그가 없다" 규칙을 없앤다.

범위 제외: 사이드바 태그 목록, 태그 이름 바꾸기·삭제(모든 노트에서 한꺼번에), 태그 범위에서 나가는 전용 버튼, 폴더와 태그를 겹친 필터, 원문 속 해시태그 인식, 에디터 칩을 눌러 범위 이동, 태그 이름 최대 길이, 검색 필터링, 태그 범위를 새로고침 뒤에도 기억하기.

## Capabilities

### New Capabilities
- `note-tags`: 노트의 태그 붙이기와 떼기, 태그 이름 규칙, 태그 저장, 카드 태그 칩, 태그 범위와 그 빈 상태, 태그 범위에서 만든 새 노트

### Modified Capabilities
- `note-ui-skeleton`: 3단 화면에서 "노트 카드는 태그 칩을 표시하지 않음" 제약 제거(사이드바 태그 목록 금지는 유지). 노트를 열면 에디터에 태그 줄이 보이도록 변경. 새 노트 만들기에 태그 범위 규칙을 넣고 "새 노트는 태그가 없다" 삭제
- `note-folders`: 사이드바 범위 항목의 active 규칙에 "태그 범위를 보는 동안에는 active 항목 없음" 추가
- `note-persistence`: 새 노트의 첫 기록 레코드가 첫 기록 시점의 태그를 갖도록 변경
