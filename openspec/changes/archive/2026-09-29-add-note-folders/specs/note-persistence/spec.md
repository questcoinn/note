## MODIFIED Requirements

### Requirement: 새 노트의 첫 기록 시점
새로 만든 노트는 원문에 공백·줄바꿈이 아닌 글자가 처음 들어갈 때까지 저장소에 기록하지 않아야 한다(MUST NOT). 이 상태의 노트를 "기록 전 새 노트"라 하며, 저장 상태는 "저장됨"으로 표시한다. 공백이 아닌 글자가 처음 들어가면 그때부터 일반 노트와 같은 자동 저장 규칙을 따르며, 이후 원문을 모두 지워도 다시 기록 전 새 노트가 되지 않는다(MUST NOT). 새 노트의 레코드는 태그가 없는 값으로, 폴더는 첫 기록 시점의 소속 폴더(`note-folders` capability에 따라 만든 범위나 사용자가 고른 폴더, 없으면 폴더 없음)로 기록한다.

#### Scenario: 입력 전에는 기록하지 않음
- **WHEN** 사용자가 "새 노트"를 누르고 아무것도 입력하지 않는다
- **THEN** 브라우저 저장소에 새 노트 레코드가 없다
- **AND** 저장 상태가 아이콘과 "저장됨" 문구로 보인다

#### Scenario: 첫 입력부터 자동 저장
- **WHEN** 사용자가 새 노트에 `# 장보기`를 입력하고 1초 동안 기다린다
- **THEN** 저장 상태가 "저장 중"을 거쳐 "저장됨"이 되고, 새로고침하면 목록에 "장보기" 노트가 있다

#### Scenario: 폴더에서 만든 새 노트의 기록
- **WHEN** 사용자가 "업무"를 보는 중에 새 노트를 만들어 `# 장보기`를 입력하고 1초 동안 기다린 뒤 새로고침한다
- **THEN** "업무"를 고르면 목록에 "장보기" 노트가 있다

#### Scenario: 입력 직후 탭 닫기
- **WHEN** 사용자가 새 노트에 글자를 입력하고 곧바로 탭을 닫은 뒤 앱을 다시 연다
- **THEN** 목록에 그 노트가 입력한 내용과 함께 있다

### Requirement: 손상되거나 알 수 없는 저장 데이터
저장된 노트 데이터 중 읽을 수 없거나 형식이 맞지 않거나 이 앱이 모르는 저장 형식 버전인 항목은 건너뛰고, 나머지 노트는 정상적으로 불러와야 한다(SHALL). 건너뛴 항목을 지우거나 덮어쓰지 않아야 한다(MUST NOT). 폴더 항목도 같은 규칙을 따르며, 노트 항목과 폴더 항목은 서로의 손상에 영향을 받지 않아야 한다(MUST NOT).

#### Scenario: 노트 하나가 손상됨
- **WHEN** 저장된 노트 7개 중 1개의 데이터가 손상된 상태에서 앱을 연다
- **THEN** 나머지 6개 노트가 목록에 보이고 열어 편집할 수 있다
- **AND** 손상된 항목의 저장 데이터는 그대로 남아 있다

#### Scenario: 손상된 폴더를 가리키는 노트
- **WHEN** 노트 A가 속한 폴더의 저장 데이터가 손상된 상태에서 앱을 연다
- **THEN** 노트 A는 "폴더 없음"으로 보이고 열어 편집할 수 있다
- **AND** 노트 A를 편집해 저장해도 저장본의 폴더 값과 손상된 폴더 데이터는 그대로다
