## MODIFIED Requirements

### Requirement: 목업 데이터로 3단 메인 화면 렌더링
시스템은 뷰포트 폭 1024px 이상에서 사이드바, 노트 목록, 에디터+미리보기 영역을 가로 3단으로 동시에 표시해야 한다(SHALL). 노트는 `note-persistence` capability에 따라, 폴더는 `note-folders` capability에 따라 저장된 데이터에서 오며, 앱은 목업 노트·폴더·태그를 포함하지 않는다(MUST NOT). 사이드바는 "새 노트" 버튼, "전체 노트"와 "폴더 없음" 항목, "폴더" 그룹을 표시하며, 구성과 동작은 `note-folders` capability를 따른다. 사이드바에 태그 목록을 표시하지 않는다(MUST NOT). 노트 카드는 태그 칩을 표시하지 않는다(MUST NOT). 저장본에 태그 값이 남아 있는 노트도 같다.

#### Scenario: 넓은 화면 첫 진입
- **WHEN** 사용자가 노트가 저장된 브라우저에서 1280px 폭으로 앱을 연다
- **THEN** 사이드바에 "새 노트" 버튼, 노트 수가 붙은 "전체 노트"와 "폴더 없음" 항목, "폴더" 그룹이 보이고, 태그 목록은 보이지 않는다
- **AND** 제목이 "전체 노트"인 노트 목록에 검색 입력과 노트 카드들이 제목, 미리보기 문장, 수정 시각 문구와 함께 보이고 태그 칩은 보이지 않는다
- **AND** 에디터 영역은 노트 미선택 상태로 보인다

#### Scenario: 외부 요청 없음
- **WHEN** 앱이 로드되고 사용자가 모든 UI를 조작한다
- **THEN** 네트워크 요청이 발생하지 않는다
- **AND** 브라우저 저장소 쓰기와 지우기는 `note-persistence` capability가 정한 노트 저장과 삭제, `note-folders` capability가 정한 폴더 저장과 삭제에서만 발생한다

### Requirement: 노트 선택과 원문 편집
노트 카드를 활성화하면 해당 카드가 selected 상태로 표시되고 에디터 영역에 그 노트의 마크다운 원문과 원문에서 렌더링된 미리보기가 나란히 표시되어야 한다(SHALL). 원문 영역은 모노스페이스 글꼴을 사용해야 한다(MUST). 원문을 수정하면 미리보기와 해당 노트 카드의 제목·미리보기 문장이 즉시 갱신되어야 하며(SHALL), 렌더링과 파생 규칙은 `markdown-preview` capability를 따른다. 원문을 수정하면 그 노트의 수정 시각이 수정한 시각으로 바뀌고 카드의 수정 시각 문구도 그에 맞게 갱신되어야 한다(SHALL). 원문 수정은 사이드바의 어떤 노트 개수도 바꾸지 않아야 한다(MUST NOT change).

#### Scenario: 카드 클릭으로 노트 열기
- **WHEN** 사용자가 노트 목록에서 카드 하나를 클릭하거나 키보드로 포커스 후 Enter를 누른다
- **THEN** 그 카드만 selected 배경으로 표시된다
- **AND** 에디터 영역 왼쪽에 해당 노트의 마크다운 원문이, 오른쪽에 렌더링된 미리보기가 표시된다
- **AND** 에디터 상단에 폴더 선택, 저장 상태 표시, 서식 도구 버튼 6종(굵게, 기울임, 제목, 링크, 목록, 코드), 삭제 버튼이 보인다

#### Scenario: 원문을 고치면 미리보기와 카드가 바뀜
- **WHEN** 사용자가 이틀 전에 마지막으로 고친 노트의 원문 영역에 글자를 입력한다
- **THEN** 미리보기와 해당 노트 카드의 제목·미리보기 문장이 입력 내용을 반영한다
- **AND** 해당 카드의 수정 시각 문구가 "방금 전"으로 바뀐다
- **AND** 사이드바의 노트 개수는 모두 그대로다

#### Scenario: 서식 도구와 사이드바 항목은 동작하지 않음
- **WHEN** 사용자가 서식 도구 버튼을 누른다
- **THEN** 원문, 목록 내용, 선택 노트는 바뀌지 않는다 (hover/focus/active 시각 상태만 나타난다)
- **WHEN** 사용자가 사이드바의 범위 항목("전체 노트", "폴더 없음", 폴더)을 누른다
- **THEN** 원문과 선택 노트는 바뀌지 않는다. 목록 범위는 `note-folders` capability에 따라 바뀐다

### Requirement: 새 노트 만들기
사이드바, 에디터 빈 상태, 목록 빈 상태의 "새 노트" 버튼을 누르면 원문이 비어 있는 새 노트가 만들어져야 한다(SHALL). 새 노트는 목록 맨 위에 "제목 없음" 카드로 selected 상태로 나타나고, 에디터에 열리며, 원문 영역에 포커스가 가야 한다(SHALL). 폴더를 보고 있을 때 만든 새 노트는 그 폴더에 속하고, "전체 노트"나 "폴더 없음"을 보고 있을 때 만든 새 노트는 폴더가 없다(SHALL). 새 노트는 태그가 없다. 좁은 화면에서는 노트 상세가 전체 폭으로 열리고 편집 탭이 선택되어야 하며(SHALL), 사이드바 오버레이가 열려 있었다면 닫혀야 한다(SHALL). 선택된 노트가 아직 아무것도 입력하지 않은 새 노트(`note-persistence`의 "기록 전 새 노트")이면 "새 노트"를 눌러도 노트를 더 만들지 않고 그 노트의 원문 영역으로 포커스만 옮겨야 한다(MUST).

#### Scenario: 사이드바에서 새 노트
- **WHEN** 1280px 폭에서 "전체 노트"를 보며 노트 A를 연 상태로 사이드바의 "새 노트" 버튼을 누른다
- **THEN** 목록 맨 위에 "제목 없음" 카드가 selected로 나타나고 노트 A 카드는 selected가 아니다
- **AND** 에디터에 빈 원문 영역과 빈 미리보기가 보이고 원문 영역에 포커스가 있으며, 폴더 선택에 "폴더 없음"이 보인다
- **AND** "전체 노트"와 "폴더 없음" 개수가 각각 1 늘어난다

#### Scenario: 폴더를 보면서 새 노트
- **WHEN** 사용자가 "업무"를 보고 있는 상태에서 "새 노트"를 누른다
- **THEN** 업무 목록 맨 위에 "제목 없음" 카드가 selected로 나타나고 폴더 선택에 "업무"가 보인다
- **AND** "업무" 개수가 1 늘어난다

#### Scenario: 입력하면 제목이 생김
- **WHEN** 사용자가 새 노트의 원문에 `# 장보기`를 입력한다
- **THEN** 카드 제목이 "장보기"로 바뀌고 수정 시각 문구는 "방금 전"이다

#### Scenario: 좁은 폭에서 새 노트
- **WHEN** 375px 폭에서 사용자가 사이드바 오버레이를 열고 "새 노트"를 누른다
- **THEN** 사이드바가 닫히고 새 노트의 상세가 편집 탭이 선택된 채 전체 폭으로 보이며 원문 영역에 포커스가 있다

#### Scenario: 빈 새 노트에서 다시 누름
- **WHEN** 사용자가 "새 노트"를 누른 뒤 아무것도 입력하지 않고 다시 "새 노트"를 누른다
- **THEN** 목록에는 "제목 없음" 카드가 하나만 있고 원문 영역에 포커스가 있다

### Requirement: 노트 미선택 빈 상태
선택된 노트가 없을 때 에디터 영역은 다음 행동을 알려주는 빈 상태 문구를 표시해야 한다(SHALL). 목록 영역의 빈 상태가 "새 노트" 버튼을 보여주고 있지 않으면 에디터 빈 상태에 "새 노트" 1차 버튼을 함께 보이고, 이 버튼은 `새 노트 만들기` 요구사항대로 동작해야 한다(SHALL). 목록 영역의 빈 상태(노트 없음, 빈 폴더)가 "새 노트" 버튼을 보여주고 있으면 에디터 빈 상태에는 버튼을 보이지 않아야 한다(MUST NOT).

#### Scenario: 첫 진입 시 에디터 빈 상태
- **WHEN** 노트가 하나 이상 있고 선택된 노트가 없다
- **THEN** 에디터 영역에 "노트를 선택하거나 새로 만들어 보세요" 문구와 "새 노트" 1차 버튼이 보인다

#### Scenario: 노트가 없으면 에디터에는 버튼 없음
- **WHEN** 1280px 폭에서 노트가 하나도 없다
- **THEN** 에디터 영역에 "노트를 선택하거나 새로 만들어 보세요" 문구만 보이고 "새 노트" 버튼은 보이지 않는다
- **AND** "새 노트" 버튼은 사이드바와 목록 영역에만 보인다

#### Scenario: 빈 폴더를 보면 에디터에는 버튼 없음
- **WHEN** 1280px 폭에서 선택된 노트 없이 노트가 없는 폴더를 보고 있다
- **THEN** 에디터 영역에는 "새 노트" 버튼이 보이지 않고, 목록 영역의 빈 폴더 상태에 "새 노트" 버튼이 보인다

#### Scenario: 빈 상태에서 새 노트
- **WHEN** 1280px 폭에서 노트가 있고 선택된 노트가 없을 때 에디터 영역의 "새 노트" 버튼을 누른다
- **THEN** 새 노트가 에디터에 열리고 원문 영역에 포커스가 있다

### Requirement: 노트 없음 빈 상태
노트가 하나도 없고 목록 범위가 "전체 노트" 또는 "폴더 없음"이면 목록 영역에 노트가 없다는 사실과 새 노트를 만들 수 있다는 안내를 "새 노트" 버튼과 함께 보여야 한다(SHALL). 폴더 범위의 빈 상태와 "폴더 없음" 범위에서 다른 폴더에만 노트가 있는 경우는 `note-folders` capability의 범위별 빈 상태를 따른다. 검색 결과 없음 강제 상태(`?search=empty`)가 켜져 있으면 그 상태가 우선한다.

#### Scenario: 처음 연 앱의 목록
- **WHEN** 저장된 노트가 없는 브라우저에서 1280px 폭으로 앱을 연다
- **THEN** 목록 영역에 노트가 없다는 문구와 "새 노트" 버튼이 보이고, 노트 카드는 보이지 않는다
- **AND** 사이드바의 "전체 노트" 개수는 0이다

#### Scenario: 마지막 노트를 지움
- **WHEN** "전체 노트"를 보는 중에 노트가 하나뿐인 상태에서 사용자가 그 노트를 삭제한다
- **THEN** 목록 영역에 노트 없음 빈 상태가 보인다
