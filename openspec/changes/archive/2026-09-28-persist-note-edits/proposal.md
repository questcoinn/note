## Why

지금은 노트 원문이 세션 메모리에만 있어서 새로고침하면 편집한 내용이 모두 사라진다. 에디터 상단의 저장 상태 표시도 실제 저장과 연결되지 않아 "편집하면 무조건 저장 안 됨"으로만 동작한다. 사용자가 쓴 글이 남아 있어야 노트 앱의 "다시 읽는" 경험을 검증할 수 있다. 첫 단계는 가장 단순한 브라우저 로컬 저장소로 가되, 나중에 IndexedDB·파일·서버로 옮길 때 저장소 교체만으로 끝나는 구조를 갖춘다.

## What Changes

- 노트 원문을 브라우저 localStorage에 자동 저장한다. 새로고침하거나 창을 다시 열어도 편집한 원문이 유지된다.
- 저장은 입력이 잠시 멈추면 자동으로 일어나고, 계속 입력해도 일정 시간마다 한 번은 저장된다. 탭 숨김, 창 닫기, 다른 노트로 전환, `Cmd/Ctrl+S`를 누르면 기다리지 않고 바로 저장한다.
- 저장소가 비어 있는 첫 실행에서는 목업 노트를 초기 데이터로 기록하고, 그 뒤로는 저장본을 사용한다.
- 저장 상태 표시가 실제 저장과 연결된다. 저장 대기와 저장 진행은 "저장 중", 완료는 "저장됨", 쓰기 실패는 "저장 안 됨"으로 표시한다. **BREAKING**(동작): 편집만으로는 더 이상 "저장 안 됨"이 되지 않는다.
- 노트에 실제 수정 시각(`updatedAt`)이 생긴다. 목록 카드의 수정 시각 문구는 이 값에서 파생되어 시간이 지나면 갱신된다. **BREAKING**(내부 데이터 모양): 목업의 `updatedLabel` 문자열 필드를 제거한다.
- 노트 목록을 최근 수정 순으로 정렬한다. 단, 지금 선택된 노트는 편집하는 동안 목록 위치가 고정되고, 선택을 벗어나면 새 위치로 이동한다.
- 저장 상태를 강제로 보여주던 개발용 `?save=` URL 쿼리를 제거한다. `?search=empty`, `?folder=empty`는 유지한다.
- 저장 계층은 비동기 저장소 인터페이스(불러오기·쓰기·지우기) 뒤에 둔다. 자동 저장 정책(대기, 즉시 저장, 상태)은 저장소 구현과 분리한다. 다음 변경의 삭제 기능을 위해 저장소의 지우기와 대기 중인 저장 취소를 미리 구현해 둔다.

범위 제외: 새 노트 만들기와 노트 삭제의 실제 동작, 폴더/태그 개수 재계산, 여러 탭에서 같은 노트를 동시에 편집할 때의 충돌 처리(마지막 쓰기가 남음), 저장소 용량 관리, 내보내기·가져오기, 다른 저장소(IndexedDB·파일·서버) 구현.

가정: 대기 시간 500ms와 최대 대기 2초는 초기값이며 사용하면서 조정할 수 있다.

## Capabilities

### New Capabilities
- `note-persistence`: 노트 원문의 로컬 영속 저장 — 첫 실행 초기화, 자동 저장 시점과 즉시 저장 계기, 쓰기 실패와 손상된 저장 데이터 처리, 저장 상태 전이

### Modified Capabilities
- `note-ui-skeleton`: "목업 데이터로 3단 메인 화면 렌더링"의 "브라우저 저장소 쓰기 없음" 시나리오를 노트 저장 외에는 쓰기가 없다는 내용으로 변경. "노트 선택과 원문 편집"의 "수정 시각 문구·노트 순서 불변" 규칙을 수정 시각 갱신과 선택 중 위치 고정 정렬로 변경. "저장 상태 표시 3종"을 실제 저장 상태 기준으로 바꾸고 `?save=` 강제 변형을 제거
- `markdown-preview`: "입력 즉시 미리보기 갱신"의 "새로고침하면 목업 초기값으로 돌아간다"를 "새로고침해도 편집한 원문이 유지된다"로 변경

## Impact

- 코드: 저장소 인터페이스와 localStorage 구현 모듈, 자동 저장 조율 모듈 신설. `src/lib/notes.svelte.ts`(수정 시각, 저장본에서 노트 구성), `src/lib/mock/data.ts`(`updatedLabel` 제거, 초기 수정 시각 표현), `src/lib/ui-state.svelte.ts`(`?save=` 강제 제거), `src/main.ts`(저장본을 불러온 뒤 화면 마운트), `src/lib/layout/EditorPane.svelte`(저장 상태 연결, 저장 단축키), `src/lib/layout/NoteList.svelte`(정렬), `src/lib/components/NoteCard.svelte`(수정 시각 문구 파생)
- 의존성: 추가 없음
- 디자인 계약: DESIGN.md는 수정하지 않는다. `save-status-indicator`의 기존 세 변형(saved, saving, unsaved)을 그대로 쓴다
- 저장 데이터: localStorage에 노트별 레코드를 스키마 버전과 함께 기록한다. 이후 저장 형식이 바뀌면 이 버전으로 이관한다
