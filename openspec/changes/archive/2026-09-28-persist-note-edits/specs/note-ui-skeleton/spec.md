## MODIFIED Requirements

### Requirement: 목업 데이터로 3단 메인 화면 렌더링
시스템은 뷰포트 폭 1024px 이상에서 사이드바, 노트 목록, 에디터+미리보기 영역을 가로 3단으로 동시에 표시해야 한다(SHALL). 폴더와 태그는 앱에 포함된 정적 목업 데이터에서 오고, 노트는 `note-persistence` capability에 따라 저장된 노트(첫 실행에서는 목업 노트)에서 온다. 목업 데이터는 폴더 3개(그중 하나는 노트가 없음), 태그 4~5개, 노트 6~8개를 포함해야 한다(MUST).

#### Scenario: 넓은 화면 첫 진입
- **WHEN** 사용자가 1280px 폭에서 앱을 연다
- **THEN** 사이드바에 "새 노트" 버튼, "전체 노트" 항목, 폴더 목록, 태그 목록이 항목별 노트 수와 함께 보인다
- **AND** 노트 목록에 검색 입력과 노트 카드들이 제목, 미리보기 문장, 수정 시각 문구, 태그 칩과 함께 보인다
- **AND** 에디터 영역은 노트 미선택 상태로 보인다

#### Scenario: 외부 요청 없음
- **WHEN** 앱이 로드되고 사용자가 모든 UI를 조작한다
- **THEN** 네트워크 요청이 발생하지 않는다
- **AND** 브라우저 저장소 쓰기는 `note-persistence` capability가 정한 노트 저장에서만 발생한다

### Requirement: 노트 선택과 원문 편집
노트 카드를 활성화하면 해당 카드가 selected 상태로 표시되고 에디터 영역에 그 노트의 마크다운 원문과 원문에서 렌더링된 미리보기가 나란히 표시되어야 한다(SHALL). 원문 영역은 모노스페이스 글꼴을 사용해야 한다(MUST). 원문을 수정하면 미리보기와 해당 노트 카드의 제목·미리보기 문장이 즉시 갱신되어야 하며(SHALL), 렌더링과 파생 규칙은 `markdown-preview` capability를 따른다. 원문을 수정하면 그 노트의 수정 시각이 수정한 시각으로 바뀌고 카드의 수정 시각 문구도 그에 맞게 갱신되어야 한다(SHALL). 원문 수정은 폴더/태그 개수를 바꾸지 않아야 한다(MUST NOT change).

#### Scenario: 카드 클릭으로 노트 열기
- **WHEN** 사용자가 노트 목록에서 카드 하나를 클릭하거나 키보드로 포커스 후 Enter를 누른다
- **THEN** 그 카드만 selected 배경으로 표시된다
- **AND** 에디터 영역 왼쪽에 해당 노트의 마크다운 원문이, 오른쪽에 렌더링된 미리보기가 표시된다
- **AND** 에디터 상단에 저장 상태 표시, 서식 도구 버튼 6종(굵게, 기울임, 제목, 링크, 목록, 코드), 삭제 버튼이 보인다

#### Scenario: 원문을 고치면 미리보기와 카드가 바뀜
- **WHEN** 사용자가 "3일 전" 노트의 원문 영역에 글자를 입력한다
- **THEN** 미리보기와 해당 노트 카드의 제목·미리보기 문장이 입력 내용을 반영한다
- **AND** 해당 카드의 수정 시각 문구가 "방금 전"으로 바뀐다
- **AND** 사이드바의 개수는 그대로다

#### Scenario: 서식 도구와 사이드바 항목은 동작하지 않음
- **WHEN** 사용자가 서식 도구 버튼, 폴더/태그 항목, 태그 칩, "새 노트" 버튼을 누른다
- **THEN** 원문, 목록 내용, 선택 노트는 바뀌지 않는다 (hover/focus/active 시각 상태만 나타난다)

## ADDED Requirements

### Requirement: 실제 저장 상태 표시
에디터의 저장 상태 표시는 저장됨, 저장 중, 저장 안 됨 세 변형을 아이콘과 문구를 함께 사용해 표시해야 한다(SHALL). 어떤 변형을 보일지는 선택된 노트의 실제 저장 상태로 정하며, 전이 규칙은 `note-persistence` capability를 따른다. 저장됨은 success 색, 저장 중은 muted 색, 저장 안 됨은 danger 색이다. URL 쿼리로 저장 상태를 강제하지 않는다. 이 표시는 클릭할 수 없어야 한다(MUST NOT be interactive).

#### Scenario: 기본 저장 상태
- **WHEN** 앱을 연 뒤 편집하지 않은 노트를 선택한다
- **THEN** 아이콘과 "저장됨" 문구가 success 색으로 보인다

#### Scenario: 편집 중과 저장 완료
- **WHEN** 사용자가 원문에 글자를 입력한다
- **THEN** 아이콘과 "저장 중" 문구가 muted 색으로 보인다
- **WHEN** 입력을 멈추고 저장이 끝난다
- **THEN** 아이콘과 "저장됨" 문구가 success 색으로 보인다

#### Scenario: 저장 실패
- **WHEN** 선택된 노트의 저장이 실패한다
- **THEN** 아이콘과 "저장 안 됨" 문구가 danger 색으로 보인다

#### Scenario: 강제 쿼리 무시
- **WHEN** URL에 `?save=saving` 또는 `?save=unsaved`가 있고 사용자가 편집하지 않은 노트를 선택한다
- **THEN** "저장됨"이 보인다

### Requirement: 최근 수정 순 목록과 편집 중 위치 고정
노트 목록은 수정 시각이 최근인 노트가 위에 오도록 정렬해야 한다(SHALL). 단, 선택된 노트는 선택된 동안 목록에서의 위치가 바뀌지 않아야 하며(MUST NOT move), 다른 노트를 열거나 노트 선택을 벗어나면 그 노트의 현재 수정 시각에 맞는 위치로 이동해야 한다(SHALL). 새로고침하면 모든 노트가 수정 시각 순으로 보인다.

#### Scenario: 편집하는 동안 제자리
- **WHEN** 1280px 폭에서 사용자가 목록 다섯 번째 노트 C를 열고 원문을 편집한다
- **THEN** 노트 C 카드는 목록 다섯 번째 자리에 그대로 있고 수정 시각 문구만 "방금 전"으로 바뀐다

#### Scenario: 다른 노트를 열면 이동
- **WHEN** 노트 C를 편집한 뒤 사용자가 다른 노트 D를 연다
- **THEN** 노트 C 카드가 목록 맨 위로 이동하고 노트 D 카드가 selected로 표시된다

#### Scenario: 좁은 폭에서 목록으로 돌아가기
- **WHEN** 375px 폭에서 사용자가 노트 C를 편집한 뒤 뒤로 가기 버튼을 누른다
- **THEN** 다시 보이는 노트 목록의 맨 위에 노트 C가 있다

#### Scenario: 편집하지 않은 노트는 순서 유지
- **WHEN** 사용자가 노트 C를 열었다가 편집하지 않고 다른 노트를 연다
- **THEN** 노트 C의 목록 위치는 바뀌지 않는다

### Requirement: 수정 시각 문구
노트 카드의 수정 시각 문구는 노트의 수정 시각과 현재 시각에서 파생해야 하며(SHALL), 화면을 열어 둔 채 시간이 지나도 1분 이내에 갱신되어야 한다(SHALL). 문구 규칙은 다음과 같다.

- 1분 미만: "방금 전"
- 1분 이상 1시간 미만: "N분 전"
- 1시간 이상이고 오늘: "N시간 전"
- 어제(달력 기준): "어제"
- 2~6일 전(달력 기준): "N일 전"
- 그보다 이전이고 올해: "M월 D일"
- 올해가 아님: "YYYY년 M월 D일"

#### Scenario: 시간이 지나면 문구 갱신
- **WHEN** 사용자가 노트를 편집해 카드에 "방금 전"이 보인 뒤 화면을 3분 동안 그대로 둔다
- **THEN** 카드 문구가 "3분 전"(또는 "2분 전")으로 바뀌어 있다

#### Scenario: 지난 날짜
- **WHEN** 오늘이 9월 28일이고 노트의 수정 시각이 9월 14일이다
- **THEN** 카드 문구는 "9월 14일"이다

## REMOVED Requirements

### Requirement: 저장 상태 표시 3종
**Reason**: 영속 저장이 생겨 "편집하면 저장 안 됨" 규칙과 `?save=` 강제 변형이 실제 저장 상태와 맞지 않게 되었다.
**Migration**: "실제 저장 상태 표시" 요구사항과 `note-persistence` capability의 "저장 상태 전이"로 대체한다. 세 변형과 색은 그대로 유지한다.
