## Why

UI 뼈대 단계의 미리보기는 손으로 적은 정적 HTML이라, 원문을 고쳐도 미리보기와 목록이 반응하지 않는다. 노트 앱의 핵심인 "쓰면서 바로 확인하는" 경험을 검증하려면 원문이 유일한 원본이 되고, 미리보기와 목록 카드가 원문에서 실시간으로 파생되어야 한다.

## What Changes

- 노트 데이터를 정적 상수에서 세션 메모리 상태로 전환한다. 원문(마크다운)이 노트 내용의 유일한 원본이 된다. 새로고침하면 목업 초기값으로 돌아간다(영속화 없음).
- 원문을 입력하는 즉시 미리보기가 다시 렌더링된다.
- 노트 제목과 목록 미리보기 문장을 원문에서 파생한다. 제목은 첫 `#` 제목, 없으면 첫 줄, 그것도 없으면 "제목 없음"이다. **BREAKING**(내부 데이터 모양): 목업의 `previewHtml`, `snippet`, `title` 필드를 제거한다.
- CommonMark와 GFM 확장(표, 취소선, 체크박스, URL 자동 링크)을 렌더링한다. 체크박스는 보기 전용이다.
- 보안: 원문에 쓴 HTML 태그는 글자 그대로 보이고, 렌더 결과는 정화한 뒤 삽입한다. `javascript:` 같은 위험한 링크는 동작하지 않는다.
- 이미지 문법은 외부 이미지를 불러오지 않고 대체 텍스트로 표시한다.
- 미리보기 링크는 새 창에서 열린다.
- 이번 세션에서 편집한 노트의 저장 상태는 "저장 안 됨"으로 표시한다. 실제로 저장되지 않기 때문이다.
- 미리보기에 새로 나타날 수 있는 요소(표, 구분선, 취소선, 굵게/기울임, h5·h6, 체크박스, 이미지 대체 텍스트)에 DESIGN.md 토큰 기반 스타일을 추가한다.

범위 제외: 영속 저장, 수정 시각 갱신과 목록 정렬, 폴더/태그 개수 재계산, 서식 도구 버튼 동작, 원문-미리보기 스크롤 싱크, 코드 구문 하이라이팅, 이미지 첨부, 체크박스 클릭으로 원문 수정.

## Capabilities

### New Capabilities
- `markdown-preview`: 마크다운 원문을 실시간으로 미리보기에 렌더링하는 규칙 — 지원 문법, 원문 HTML·위험 링크 처리, 이미지·링크·체크박스 동작, 제목과 미리보기 문장 파생

### Modified Capabilities
- `note-ui-skeleton`: "노트 선택은 표시만 바꾼다"를 제거하고 원문 편집이 미리보기와 목록 카드에 반영되는 "노트 선택과 원문 편집"으로 대체. "저장 상태 표시 3종" — 편집한 노트는 "저장 안 됨"으로 바뀌는 규칙 추가

## Impact

- 코드: `src/lib/mock/data.ts`(노트 타입과 목업 필드 정리), 노트 상태 모듈 신설, `src/lib/layout/EditorPane.svelte`(원문 바인딩, 렌더 결과 삽입, 미리보기 스타일 추가), `src/lib/components/NoteCard.svelte`·`src/lib/layout/NoteList.svelte`·`src/lib/layout/Sidebar.svelte`(상수 대신 상태 참조), 마크다운 렌더 모듈 신설
- 의존성: 런타임 의존성 `markdown-it`, `dompurify` 추가 (프로젝트 최초의 런타임 의존성)
- 디자인 계약: DESIGN.md는 수정하지 않는다. 추가 미리보기 스타일은 기존 토큰만 사용한다
