## ADDED Requirements

### Requirement: 새 노트의 첫 기록 시점
새로 만든 노트는 원문에 공백·줄바꿈이 아닌 글자가 처음 들어갈 때까지 저장소에 기록하지 않아야 한다(MUST NOT). 이 상태의 노트를 "기록 전 새 노트"라 하며, 저장 상태는 "저장됨"으로 표시한다. 공백이 아닌 글자가 처음 들어가면 그때부터 일반 노트와 같은 자동 저장 규칙을 따르며, 이후 원문을 모두 지워도 다시 기록 전 새 노트가 되지 않는다(MUST NOT). 새 노트의 레코드는 폴더와 태그가 없는 값으로 기록한다.

#### Scenario: 입력 전에는 기록하지 않음
- **WHEN** 사용자가 "새 노트"를 누르고 아무것도 입력하지 않는다
- **THEN** 브라우저 저장소에 새 노트 레코드가 없다
- **AND** 저장 상태가 아이콘과 "저장됨" 문구로 보인다

#### Scenario: 첫 입력부터 자동 저장
- **WHEN** 사용자가 새 노트에 `# 장보기`를 입력하고 1초 동안 기다린다
- **THEN** 저장 상태가 "저장 중"을 거쳐 "저장됨"이 되고, 새로고침하면 목록에 "장보기" 노트가 있다

#### Scenario: 입력 직후 탭 닫기
- **WHEN** 사용자가 새 노트에 글자를 입력하고 곧바로 탭을 닫은 뒤 앱을 다시 연다
- **THEN** 목록에 그 노트가 입력한 내용과 함께 있다

### Requirement: 노트 삭제
노트를 삭제하면 그 노트의 저장 레코드를 저장소에서 지워야 하며(SHALL), 지운 노트는 새로고침하거나 창을 다시 열어도 돌아오지 않아야 한다(MUST NOT). 삭제 전에 그 노트의 저장 대기나 진행 중인 저장이 있었다면, 삭제 뒤에 그 저장이 레코드를 다시 만들지 않아야 한다(MUST NOT). 저장소에서 지우기에 실패하면 노트는 화면과 저장본에 그대로 남고 실패가 삭제를 요청한 화면에 전달되어야 한다(SHALL). 기록 전 새 노트를 정리할 때는 저장소를 건드리지 않는다. 다른 노트의 원문과 저장 상태는 삭제의 영향을 받지 않아야 한다(MUST NOT).

#### Scenario: 삭제 후 새로고침
- **WHEN** 사용자가 노트 A를 삭제한 뒤 페이지를 새로고침한다
- **THEN** 목록에 노트 A가 없다

#### Scenario: 입력 직후 삭제
- **WHEN** 사용자가 노트 A에 글자를 입력하고 저장 상태가 "저장 중"일 때 곧바로 노트 A를 삭제한 뒤 2초 기다렸다가 새로고침한다
- **THEN** 목록에 노트 A가 없다

#### Scenario: 마지막 노트까지 삭제
- **WHEN** 사용자가 모든 노트를 삭제한 뒤 새로고침한다
- **THEN** 목록이 비어 있고 노트 없음 빈 상태가 보인다

#### Scenario: 지우기 실패
- **WHEN** 저장소에서 지우기가 실패한다
- **THEN** 노트가 목록에 그대로 있고, 새로고침해도 노트가 있다

## MODIFIED Requirements

### Requirement: 첫 실행 초기 데이터
저장된 노트가 하나도 없는 상태로 앱을 열면 노트가 없는 빈 상태로 시작해야 하며(SHALL), 앱이 스스로 노트를 만들거나 저장소에 기록하지 않아야 한다(MUST NOT). 저장된 노트 항목이 있으면(이전 버전이 첫 실행 때 기록한 예시 노트 포함) 저장본을 그대로 사용해야 한다(MUST).

#### Scenario: 처음 연 앱
- **WHEN** 저장된 노트가 없는 브라우저에서 앱을 연다
- **THEN** 목록에 노트가 없고 노트 없음 빈 상태가 보인다
- **AND** 브라우저 저장소에 노트 레코드가 기록되지 않는다

#### Scenario: 저장본이 목업보다 우선
- **WHEN** 이전 버전에서 첫 실행 때 기록된 예시 노트들이 저장된 브라우저에서 앱을 연다
- **THEN** 그 노트들이 목록에 보이고 열어서 편집하거나 삭제할 수 있다

### Requirement: 쓰기 실패 처리
저장소 용량 초과, 브라우저 설정으로 인한 저장소 차단 등으로 저장에 실패하면 해당 노트의 저장 상태를 "저장 안 됨"으로 표시해야 한다(SHALL). 실패해도 편집한 원문은 현재 세션에서 사라지지 않아야 하며(MUST NOT be lost), 사용자가 그 노트를 다시 편집하거나 즉시 저장 계기가 생기면 저장을 다시 시도해야 한다(SHALL). 앱을 열 때 저장소를 읽을 수 없으면 노트가 없는 빈 상태로 화면을 표시하고, 새 노트를 만들어 편집할 수 있되 저장 시도는 실패로 표시해야 한다(SHALL).

#### Scenario: 용량 초과
- **WHEN** 저장소 용량이 가득 찬 상태에서 사용자가 원문을 편집한다
- **THEN** 저장 상태가 아이콘과 "저장 안 됨" 문구로 danger 색으로 보인다
- **AND** 원문과 미리보기에는 편집한 내용이 그대로 남아 있다

#### Scenario: 실패 뒤 재시도 성공
- **WHEN** 저장이 실패한 뒤 저장소에 여유가 생기고 사용자가 같은 노트에 글자를 하나 더 입력한다
- **THEN** 저장 상태가 "저장 중"을 거쳐 "저장됨"이 되고, 새로고침하면 실패 전 편집까지 모두 남아 있다

#### Scenario: 저장소를 쓸 수 없는 환경
- **WHEN** 브라우저 설정으로 사이트 저장소가 차단된 상태에서 앱을 연다
- **THEN** 목록에 노트 없음 빈 상태가 보이고 새 노트를 만들어 편집할 수 있다
- **AND** 새 노트에 글자를 입력하면 저장 상태가 "저장 안 됨"이 된다
