## Why

화면에는 "새 노트" 버튼과 삭제 확인 다이얼로그가 있지만 둘 다 아무 동작도 하지 않아, 사용자는 앱이 넣어 준 목업 노트를 고치는 것 말고는 할 수 있는 일이 없다. 저장 계층에는 지우기와 대기 저장 취소가 이미 준비되어 있으므로, 이제 노트를 직접 만들고 지우는 흐름을 연결해 앱을 실제로 쓸 수 있게 한다. 사용자가 노트를 직접 만들 수 있게 되면 목업 노트·폴더·태그는 존재하지 않는 데이터를 보여주는 셈이 되므로 함께 걷어낸다.

## What Changes

- "새 노트" 버튼(사이드바, 에디터 빈 상태, 목록 빈 상태)을 누르면 빈 노트가 만들어지고, 목록 맨 위에 선택된 채로 나타나며 원문 영역에 포커스가 간다. 새 노트는 폴더·태그가 없다.
- 새로 만든 노트는 원문에 공백이 아닌 글자를 처음 입력할 때까지 저장소에 기록하지 않는다. 비어 있는 채로 선택을 벗어나거나 페이지를 떠나면 확인 없이 사라진다. 빈 새 노트가 이미 선택된 상태에서 "새 노트"를 다시 누르면 새로 만들지 않고 그 노트의 원문 영역으로 포커스만 옮긴다.
- 삭제 확인 다이얼로그의 "삭제"가 실제로 노트를 지운다. 성공하면 다이얼로그가 닫히고 노트 선택이 해제된다(넓은 화면은 에디터 빈 상태, 좁은 화면은 목록). 실패하면 다이얼로그를 닫지 않고 그 안에 실패 문구를 보여주며 다시 시도하거나 취소할 수 있다. 지운 노트는 새로고침해도 돌아오지 않는다.
- **BREAKING**(동작): 목업 노트를 제거한다. 저장된 노트가 없는 브라우저에서 처음 열면 노트가 하나도 없는 빈 상태로 시작한다. 이미 목업 노트가 저장된 브라우저에서는 그 노트들을 사용자 노트로 그대로 둔다.
- **BREAKING**(화면): 목업 폴더와 태그를 제거한다. 사이드바에는 "새 노트" 버튼과 "전체 노트" 항목만 남고, 노트 카드에 태그 칩이 표시되지 않는다. 개발용 `?folder=empty` 강제 상태와 빈 폴더 화면을 없앤다. `?search=empty`는 유지한다.
- 노트가 하나도 없을 때 목록 영역에 무엇을 할 수 있는지 알려주는 빈 상태를 보여준다.

범위 제외: 폴더·태그 기능(분류, 필터링, 개수), 검색 필터링, 새 노트 단축키, 삭제 되돌리기·휴지통, 여러 노트 한꺼번에 삭제, 목업이 이미 저장된 브라우저의 데이터 정리.

## Capabilities

### New Capabilities
(없음)

### Modified Capabilities
- `note-ui-skeleton`: 3단 메인 화면에서 목업 폴더·태그·노트를 제거하고 사이드바를 "새 노트"와 "전체 노트"로 축소. "새 노트" 버튼이 실제로 노트를 만들도록 변경하고 빈 새 노트 정리 규칙을 추가. 삭제 확인 다이얼로그가 실제로 삭제하고 실패를 다이얼로그 안에 표시하도록 변경. 삭제 후 선택 해제. 노트 없음 빈 상태 추가. 빈 폴더 상태 제거. 목업 노트를 전제한 시나리오 수정
- `note-persistence`: 첫 실행 초기 데이터를 "빈 상태로 시작"으로 변경. 저장소를 읽을 수 없을 때 목업 대신 빈 목록으로 시작. 새 노트의 첫 기록 시점과 노트 삭제의 영속화(대기 중인 저장 취소 포함) 추가
- `markdown-preview`: "제목과 미리보기 문장 파생"의 목업 노트 원문을 전제한 시나리오를 사용자가 쓴 노트 기준으로 수정

## Impact

- 코드: `src/lib/notes.svelte.ts`(노트 컬렉션을 반응형으로, 만들기·삭제·빈 새 노트 정리), `src/lib/ui-state.svelte.ts`(`?folder=empty` 제거, 삭제 흐름 상태), `src/main.ts`(목업 기록 제거), `src/lib/mock/data.ts`(노트·폴더·태그 목업 제거), `src/lib/layout/Sidebar.svelte`, `src/lib/layout/NoteList.svelte`, `src/lib/layout/EditorPane.svelte`, `src/lib/components/ConfirmDialog.svelte`(실패 문구), `src/lib/components/NoteCard.svelte`(태그 칩 제거)
- 의존성: 추가 없음
- 저장 데이터: 저장 형식(v1)은 바꾸지 않는다. 새 노트는 `folderId: ''`, `tagIds: []`로 기록한다. 기존 레코드의 `folderId`·`tagIds`는 저장본에 그대로 두고 화면에서는 쓰지 않는다
- 디자인 계약: DESIGN.md는 수정하지 않는다. `tag-chip`과 폴더/태그 변형의 `sidebar-nav-item`은 계약에 남지만 이번 화면에서는 쓰지 않는다
