## MODIFIED Requirements

### Requirement: 노트 없음 빈 상태
노트가 하나도 없고 목록 범위가 "전체 노트" 또는 "폴더 없음"이면 목록 영역에 노트가 없다는 사실과 새 노트를 만들 수 있다는 안내를 "새 노트" 버튼과 함께 보여야 한다(SHALL). 폴더 범위의 빈 상태와 "폴더 없음" 범위에서 다른 폴더에만 노트가 있는 경우는 `note-folders` capability의 범위별 빈 상태를 따른다. 검색어가 있어도 이 빈 상태가 검색 결과 없음보다 먼저다(`note-search` capability).

#### Scenario: 처음 연 앱의 목록
- **WHEN** 저장된 노트가 없는 브라우저에서 1280px 폭으로 앱을 연다
- **THEN** 목록 영역에 노트가 없다는 문구와 "새 노트" 버튼이 보이고, 노트 카드는 보이지 않는다
- **AND** 사이드바의 "전체 노트" 개수는 0이다

#### Scenario: 마지막 노트를 지움
- **WHEN** "전체 노트"를 보는 중에 노트가 하나뿐인 상태에서 사용자가 그 노트를 삭제한다
- **THEN** 목록 영역에 노트 없음 빈 상태가 보인다

#### Scenario: 노트가 없을 때 검색
- **WHEN** 저장된 노트가 없는 상태에서 사용자가 검색 입력에 글자를 넣는다
- **THEN** 목록 영역에는 검색 결과 없음이 아니라 노트 없음 빈 상태와 "새 노트" 버튼이 보인다

## REMOVED Requirements

### Requirement: 검색 결과 없음 상태
**Reason**: 검색이 실제로 목록을 필터링하므로 URL 쿼리(`?search=empty`)로 결과 없음 상태를 강제할 필요가 없고, "입력해도 필터링하지 않는다"는 제약도 더는 맞지 않는다.
**Migration**: 검색 동작과 결과 없음 빈 상태는 `note-search` capability의 "일치 규칙", "검색 결과 없음 빈 상태"를 따른다. 결과 없음 상태를 보려면 어떤 노트에도 없는 단어를 검색한다. `?search=empty` 쿼리는 무시된다.
