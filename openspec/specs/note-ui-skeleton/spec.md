# note-ui-skeleton Specification

## Purpose

노트 앱의 전체 화면 구조, 반응형 동작, 상태 문구를 정의하는 UI 뼈대. 노트 원문 편집과 미리보기 렌더링은 `markdown-preview` capability가 맡고, 노트 영속 저장은 `note-persistence` capability가 맡는다. 노트 만들기와 삭제의 화면 흐름도 여기서 정의한다. 검색처럼 아직 구현되지 않은 기능의 상태는 URL 강제 상태로 보여주어 DESIGN.md 계약을 시각적으로 검증할 수 있게 한다.

## Requirements

### Requirement: 목업 데이터로 3단 메인 화면 렌더링
시스템은 뷰포트 폭 1024px 이상에서 사이드바, 노트 목록, 에디터+미리보기 영역을 가로 3단으로 동시에 표시해야 한다(SHALL). 노트는 `note-persistence` capability에 따라, 폴더는 `note-folders` capability에 따라 저장된 데이터에서 오며, 앱은 목업 노트·폴더·태그를 포함하지 않는다(MUST NOT). 사이드바는 "새 노트" 버튼, "전체 노트"와 "폴더 없음" 항목, "폴더" 그룹을 표시하며, 구성과 동작은 `note-folders` capability를 따른다. 사이드바에 태그 목록을 표시하지 않는다(MUST NOT). 노트 카드는 태그 칩을 표시하지 않는다(MUST NOT). 저장본에 태그 값이 남아 있는 노트도 같다.

#### Scenario: 넓은 화면 첫 진입
- **WHEN** 사용자가 노트가 저장된 브라우저에서 1280px 폭으로 앱을 연다
- **THEN** 사이드바에 "새 노트" 버튼, 노트 수가 붙은 "전체 노트"와 "폴더 없음" 항목, "폴더" 그룹이 보이고, 태그 목록은 보이지 않는다
- **AND** 제목이 "전체 노트"인 노트 목록에 검색 입력과 노트 카드들이 제목, 미리보기 문장, 수정 시각 문구와 함께 보이고 태그 칩은 보이지 않는다
- **AND** 에디터 영역은 노트 미선택 상태로 보인다

#### Scenario: 외부 요청 없음
- **WHEN** 앱이 로드되고 사용자가 모든 UI를 조작한다
- **THEN** 네트워크 요청이 발생하지 않는다
- **AND** 브라우저 저장소 쓰기와 지우기는 `note-persistence` capability가 정한 노트 저장과 삭제, `note-folders` capability가 정한 폴더 저장과 삭제에서만 발생한다

### Requirement: 노트 선택과 원문 편집
노트 카드를 활성화하면 해당 카드가 selected 상태로 표시되고 에디터 영역에 그 노트의 마크다운 원문과 원문에서 렌더링된 미리보기가 나란히 표시되어야 한다(SHALL). 원문 영역은 모노스페이스 글꼴을 사용해야 한다(MUST). 원문을 수정하면 미리보기와 해당 노트 카드의 제목·미리보기 문장이 즉시 갱신되어야 하며(SHALL), 렌더링과 파생 규칙은 `markdown-preview` capability를 따른다. 원문을 수정하면 그 노트의 수정 시각이 수정한 시각으로 바뀌고 카드의 수정 시각 문구도 그에 맞게 갱신되어야 한다(SHALL). 원문 수정은 사이드바의 어떤 노트 개수도 바꾸지 않아야 한다(MUST NOT change).

#### Scenario: 카드 클릭으로 노트 열기
- **WHEN** 사용자가 노트 목록에서 카드 하나를 클릭하거나 키보드로 포커스 후 Enter를 누른다
- **THEN** 그 카드만 selected 배경으로 표시된다
- **AND** 에디터 영역 왼쪽에 해당 노트의 마크다운 원문이, 오른쪽에 렌더링된 미리보기가 표시된다
- **AND** 에디터 상단에 폴더 선택, 저장 상태 표시, 서식 도구 버튼 6종(굵게, 기울임, 제목, 링크, 목록, 코드), 삭제 버튼이 보인다

#### Scenario: 원문을 고치면 미리보기와 카드가 바뀜
- **WHEN** 사용자가 이틀 전에 마지막으로 고친 노트의 원문 영역에 글자를 입력한다
- **THEN** 미리보기와 해당 노트 카드의 제목·미리보기 문장이 입력 내용을 반영한다
- **AND** 해당 카드의 수정 시각 문구가 "방금 전"으로 바뀐다
- **AND** 사이드바의 노트 개수는 모두 그대로다

#### Scenario: 서식 도구와 사이드바 항목은 동작하지 않음
- **WHEN** 사용자가 서식 도구 버튼을 누른다
- **THEN** 원문, 목록 내용, 선택 노트는 바뀌지 않는다 (hover/focus/active 시각 상태만 나타난다)
- **WHEN** 사용자가 사이드바의 범위 항목("전체 노트", "폴더 없음", 폴더)을 누른다
- **THEN** 원문과 선택 노트는 바뀌지 않는다. 목록 범위는 `note-folders` capability에 따라 바뀐다

### Requirement: 새 노트 만들기
사이드바, 에디터 빈 상태, 목록 빈 상태의 "새 노트" 버튼을 누르면 원문이 비어 있는 새 노트가 만들어져야 한다(SHALL). 새 노트는 목록 맨 위에 "제목 없음" 카드로 selected 상태로 나타나고, 에디터에 열리며, 원문 영역에 포커스가 가야 한다(SHALL). 폴더를 보고 있을 때 만든 새 노트는 그 폴더에 속하고, "전체 노트"나 "폴더 없음"을 보고 있을 때 만든 새 노트는 폴더가 없다(SHALL). 새 노트는 태그가 없다. 좁은 화면에서는 노트 상세가 전체 폭으로 열리고 편집 탭이 선택되어야 하며(SHALL), 사이드바 오버레이가 열려 있었다면 닫혀야 한다(SHALL). 선택된 노트가 아직 아무것도 입력하지 않은 새 노트(`note-persistence`의 "기록 전 새 노트")이면 "새 노트"를 눌러도 노트를 더 만들지 않고 그 노트의 원문 영역으로 포커스만 옮겨야 한다(MUST).

#### Scenario: 사이드바에서 새 노트
- **WHEN** 1280px 폭에서 "전체 노트"를 보며 노트 A를 연 상태로 사이드바의 "새 노트" 버튼을 누른다
- **THEN** 목록 맨 위에 "제목 없음" 카드가 selected로 나타나고 노트 A 카드는 selected가 아니다
- **AND** 에디터에 빈 원문 영역과 빈 미리보기가 보이고 원문 영역에 포커스가 있으며, 폴더 선택에 "폴더 없음"이 보인다
- **AND** "전체 노트"와 "폴더 없음" 개수가 각각 1 늘어난다

#### Scenario: 폴더를 보면서 새 노트
- **WHEN** 사용자가 "업무"를 보고 있는 상태에서 "새 노트"를 누른다
- **THEN** 업무 목록 맨 위에 "제목 없음" 카드가 selected로 나타나고 폴더 선택에 "업무"가 보인다
- **AND** "업무" 개수가 1 늘어난다

#### Scenario: 입력하면 제목이 생김
- **WHEN** 사용자가 새 노트의 원문에 `# 장보기`를 입력한다
- **THEN** 카드 제목이 "장보기"로 바뀌고 수정 시각 문구는 "방금 전"이다

#### Scenario: 좁은 폭에서 새 노트
- **WHEN** 375px 폭에서 사용자가 사이드바 오버레이를 열고 "새 노트"를 누른다
- **THEN** 사이드바가 닫히고 새 노트의 상세가 편집 탭이 선택된 채 전체 폭으로 보이며 원문 영역에 포커스가 있다

#### Scenario: 빈 새 노트에서 다시 누름
- **WHEN** 사용자가 "새 노트"를 누른 뒤 아무것도 입력하지 않고 다시 "새 노트"를 누른다
- **THEN** 목록에는 "제목 없음" 카드가 하나만 있고 원문 영역에 포커스가 있다

### Requirement: 빈 새 노트 정리
원문에 공백·줄바꿈이 아닌 글자를 한 번도 입력하지 않은 새 노트는, 선택을 벗어나면(다른 노트 열기, 좁은 화면의 뒤로 가기 등) 확인 없이 목록에서 사라져야 한다(SHALL). 새로고침하거나 창을 닫았다 다시 열어도 이런 노트는 남아 있지 않아야 한다(MUST NOT remain). 공백이 아닌 글자를 한 번이라도 입력한 노트는 나중에 원문을 모두 지워도 정리 대상이 아니며 "제목 없음" 노트로 남아야 한다(MUST).

#### Scenario: 아무것도 쓰지 않고 다른 노트로
- **WHEN** 사용자가 "새 노트"를 누르고 아무것도 입력하지 않은 채 노트 A 카드를 누른다
- **THEN** "제목 없음" 카드가 목록에서 사라지고 노트 A가 열린다
- **AND** "전체 노트" 개수가 새 노트를 만들기 전과 같다

#### Scenario: 공백만 입력하고 뒤로 가기
- **WHEN** 375px 폭에서 사용자가 새 노트를 만들고 원문에 공백과 줄바꿈만 입력한 뒤 뒤로 가기 버튼을 누른다
- **THEN** 목록에 그 노트가 없다

#### Scenario: 빈 새 노트를 둔 채 새로고침
- **WHEN** 사용자가 새 노트를 만들고 아무것도 입력하지 않은 채 페이지를 새로고침한다
- **THEN** 목록에 "제목 없음" 노트가 없다

#### Scenario: 썼다가 모두 지운 노트는 남음
- **WHEN** 사용자가 새 노트에 `메모`를 입력한 뒤 원문을 모두 지우고 다른 노트를 연다
- **THEN** 목록에 "제목 없음" 카드가 남아 있다

### Requirement: 최근 수정 순 목록과 편집 중 위치 고정
노트 목록은 수정 시각이 최근인 노트가 위에 오도록 정렬해야 한다(SHALL). 단, 선택된 노트는 선택된 동안 목록에서의 위치가 바뀌지 않아야 하며(MUST NOT move), 다른 노트를 열거나 노트 선택을 벗어나면 그 노트의 현재 수정 시각에 맞는 위치로 이동해야 한다(SHALL). 새로 만든 노트는 만든 시각을 수정 시각으로 가지므로 목록 맨 위에 나타난다. 새로고침하면 모든 노트가 수정 시각 순으로 보인다.

#### Scenario: 편집하는 동안 제자리
- **WHEN** 1280px 폭에서 노트가 다섯 개 이상 있고 사용자가 목록 다섯 번째 노트 C를 열어 원문을 편집한다
- **THEN** 노트 C 카드는 목록 다섯 번째 자리에 그대로 있고 수정 시각 문구만 "방금 전"으로 바뀐다

#### Scenario: 다른 노트를 열면 이동
- **WHEN** 노트 C를 편집한 뒤 사용자가 다른 노트 D를 연다
- **THEN** 노트 C 카드가 목록 맨 위로 이동하고 노트 D 카드가 selected로 표시된다

#### Scenario: 좁은 폭에서 목록으로 돌아가기
- **WHEN** 375px 폭에서 사용자가 노트 C를 편집한 뒤 뒤로 가기 버튼을 누른다
- **THEN** 다시 보이는 노트 목록의 맨 위에 노트 C가 있다

#### Scenario: 편집하지 않은 노트는 순서 유지
- **WHEN** 사용자가 노트 C를 열었다가 편집하지 않고 다른 노트를 연다
- **THEN** 노트 C의 목록 위치는 바뀌지 않는다

### Requirement: 수정 시각 문구
노트 카드의 수정 시각 문구는 노트의 수정 시각과 현재 시각에서 파생해야 하며(SHALL), 화면을 열어 둔 채 시간이 지나도 1분 이내에 갱신되어야 한다(SHALL). 문구 규칙은 다음과 같다.

- 1분 미만: "방금 전"
- 1분 이상 1시간 미만: "N분 전"
- 1시간 이상이고 오늘: "N시간 전"
- 어제(달력 기준): "어제"
- 2~6일 전(달력 기준): "N일 전"
- 그보다 이전이고 올해: "M월 D일"
- 올해가 아님: "YYYY년 M월 D일"

#### Scenario: 시간이 지나면 문구 갱신
- **WHEN** 사용자가 노트를 편집해 카드에 "방금 전"이 보인 뒤 화면을 3분 동안 그대로 둔다
- **THEN** 카드 문구가 "3분 전"(또는 "2분 전")으로 바뀌어 있다

#### Scenario: 지난 날짜
- **WHEN** 오늘이 9월 28일이고 노트의 수정 시각이 9월 14일이다
- **THEN** 카드 문구는 "9월 14일"이다

### Requirement: 노트 미선택 빈 상태
선택된 노트가 없을 때 에디터 영역은 다음 행동을 알려주는 빈 상태 문구를 표시해야 한다(SHALL). 목록 영역의 빈 상태가 "새 노트" 버튼을 보여주고 있지 않으면 에디터 빈 상태에 "새 노트" 1차 버튼을 함께 보이고, 이 버튼은 `새 노트 만들기` 요구사항대로 동작해야 한다(SHALL). 목록 영역의 빈 상태(노트 없음, 빈 폴더)가 "새 노트" 버튼을 보여주고 있으면 에디터 빈 상태에는 버튼을 보이지 않아야 한다(MUST NOT).

#### Scenario: 첫 진입 시 에디터 빈 상태
- **WHEN** 노트가 하나 이상 있고 선택된 노트가 없다
- **THEN** 에디터 영역에 "노트를 선택하거나 새로 만들어 보세요" 문구와 "새 노트" 1차 버튼이 보인다

#### Scenario: 노트가 없으면 에디터에는 버튼 없음
- **WHEN** 1280px 폭에서 노트가 하나도 없다
- **THEN** 에디터 영역에 "노트를 선택하거나 새로 만들어 보세요" 문구만 보이고 "새 노트" 버튼은 보이지 않는다
- **AND** "새 노트" 버튼은 사이드바와 목록 영역에만 보인다

#### Scenario: 빈 폴더를 보면 에디터에는 버튼 없음
- **WHEN** 1280px 폭에서 선택된 노트 없이 노트가 없는 폴더를 보고 있다
- **THEN** 에디터 영역에는 "새 노트" 버튼이 보이지 않고, 목록 영역의 빈 폴더 상태에 "새 노트" 버튼이 보인다

#### Scenario: 빈 상태에서 새 노트
- **WHEN** 1280px 폭에서 노트가 있고 선택된 노트가 없을 때 에디터 영역의 "새 노트" 버튼을 누른다
- **THEN** 새 노트가 에디터에 열리고 원문 영역에 포커스가 있다

### Requirement: 노트 없음 빈 상태
노트가 하나도 없고 목록 범위가 "전체 노트" 또는 "폴더 없음"이면 목록 영역에 노트가 없다는 사실과 새 노트를 만들 수 있다는 안내를 "새 노트" 버튼과 함께 보여야 한다(SHALL). 폴더 범위의 빈 상태와 "폴더 없음" 범위에서 다른 폴더에만 노트가 있는 경우는 `note-folders` capability의 범위별 빈 상태를 따른다. 검색 결과 없음 강제 상태(`?search=empty`)가 켜져 있으면 그 상태가 우선한다.

#### Scenario: 처음 연 앱의 목록
- **WHEN** 저장된 노트가 없는 브라우저에서 1280px 폭으로 앱을 연다
- **THEN** 목록 영역에 노트가 없다는 문구와 "새 노트" 버튼이 보이고, 노트 카드는 보이지 않는다
- **AND** 사이드바의 "전체 노트" 개수는 0이다

#### Scenario: 마지막 노트를 지움
- **WHEN** "전체 노트"를 보는 중에 노트가 하나뿐인 상태에서 사용자가 그 노트를 삭제한다
- **THEN** 목록 영역에 노트 없음 빈 상태가 보인다

### Requirement: 검색 결과 없음 상태
검색 기능 없이 검색 결과 없음 상태를 URL 쿼리로 강제 표시할 수 있어야 한다(SHALL). 검색 입력에 글자를 입력해도 목록은 필터링되지 않아야 한다(MUST NOT filter).

#### Scenario: 강제 결과 없음
- **WHEN** URL에 `?search=empty`가 있다
- **THEN** 검색 입력에 예시 검색어가 채워지고 지우기 버튼이 보인다
- **AND** 목록 영역에 "일치하는 노트가 없어요" 문구가 보이고 노트 카드는 보이지 않는다

#### Scenario: 입력해도 필터링 안 됨
- **WHEN** 쿼리 없이 사용자가 검색 입력에 글자를 입력한다
- **THEN** 입력값은 표시되지만 목록의 노트 카드는 그대로다

### Requirement: 실제 저장 상태 표시
에디터의 저장 상태 표시는 저장됨, 저장 중, 저장 안 됨 세 변형을 아이콘과 문구를 함께 사용해 표시해야 한다(SHALL). 어떤 변형을 보일지는 선택된 노트의 실제 저장 상태로 정하며, 전이 규칙은 `note-persistence` capability를 따른다. 저장됨은 success 색, 저장 중은 muted 색, 저장 안 됨은 danger 색이다. URL 쿼리로 저장 상태를 강제하지 않는다. 이 표시는 클릭할 수 없어야 한다(MUST NOT be interactive).

#### Scenario: 기본 저장 상태
- **WHEN** 앱을 연 뒤 편집하지 않은 노트를 선택한다
- **THEN** 아이콘과 "저장됨" 문구가 success 색으로 보인다

#### Scenario: 편집 중과 저장 완료
- **WHEN** 사용자가 원문에 글자를 입력한다
- **THEN** 아이콘과 "저장 중" 문구가 muted 색으로 보인다
- **WHEN** 입력을 멈추고 저장이 끝난다
- **THEN** 아이콘과 "저장됨" 문구가 success 색으로 보인다

#### Scenario: 저장 실패
- **WHEN** 선택된 노트의 저장이 실패한다
- **THEN** 아이콘과 "저장 안 됨" 문구가 danger 색으로 보인다

#### Scenario: 강제 쿼리 무시
- **WHEN** URL에 `?save=saving` 또는 `?save=unsaved`가 있고 사용자가 편집하지 않은 노트를 선택한다
- **THEN** "저장됨"이 보인다

### Requirement: 삭제 확인 다이얼로그
에디터의 삭제 버튼은 결과를 먼저 구체적으로 말하는 확인 다이얼로그를 열어야 한다(SHALL). 다이얼로그는 모달이며 열려 있는 동안 포커스가 다이얼로그 안에 머물고 Esc로 닫혀야 한다(MUST). "취소"나 Esc는 아무것도 지우지 않고 다이얼로그만 닫아야 한다(MUST). "삭제"를 누르면 `note-persistence` capability에 따라 노트를 지우고, 성공하면 다이얼로그를 닫고 그 노트를 목록과 에디터에서 없애며 노트 선택을 해제해야 한다(SHALL). 선택이 해제되면 넓은 화면에서는 에디터 빈 상태가, 좁은 화면에서는 노트 목록이 보이고, 포커스는 노트 목록 영역으로 옮겨야 한다(SHALL). 삭제에 실패하면 다이얼로그를 닫지 않고 노트를 그대로 둔 채 다이얼로그 안에 아이콘과 함께 삭제하지 못했다는 문구를 danger 색으로 보여주고, 보조 기술에 즉시 알려야 한다(MUST). 이때 "삭제" 버튼은 다시 시도하는 버튼이 되고 "취소"로 닫을 수 있다. 다이얼로그를 다시 열면 실패 문구는 보이지 않는다.

#### Scenario: 삭제 확인 열고 닫기
- **WHEN** 사용자가 노트를 선택한 뒤 삭제 버튼을 누른다
- **THEN** 선택된 노트 제목을 포함해 삭제하면 되돌릴 수 없다는 문구, danger 스타일 "삭제" 버튼, "취소" 버튼이 있는 모달이 열린다
- **WHEN** 사용자가 "취소" 또는 Esc를 누른다
- **THEN** 다이얼로그가 닫히고 노트는 목록과 에디터에 그대로 남는다

#### Scenario: 넓은 화면에서 삭제
- **WHEN** 1280px 폭에서 사용자가 노트 A의 삭제 확인 다이얼로그에서 "삭제"를 누른다
- **THEN** 다이얼로그가 닫히고 노트 A 카드가 목록에서 사라진다
- **AND** 에디터 영역에 "노트를 선택하거나 새로 만들어 보세요" 빈 상태가 보이고, 포커스가 노트 목록 영역에 있다
- **AND** "전체 노트" 개수가 1 줄어든다

#### Scenario: 좁은 화면에서 삭제
- **WHEN** 375px 폭에서 사용자가 노트 상세의 삭제 확인 다이얼로그에서 "삭제"를 누른다
- **THEN** 노트 목록이 전체 폭으로 보이고 지운 노트는 목록에 없다

#### Scenario: 삭제 실패
- **WHEN** 브라우저 저장소를 쓸 수 없는 상태에서 사용자가 삭제 확인 다이얼로그의 "삭제"를 누른다
- **THEN** 다이얼로그는 열린 채로 아이콘과 삭제하지 못했다는 문구가 danger 색으로 보이고 스크린 리더가 그 문구를 읽는다
- **AND** 노트는 목록과 에디터에 그대로 있다
- **WHEN** 사용자가 "취소"를 누른다
- **THEN** 다이얼로그가 닫히고 노트는 그대로 선택되어 있다

### Requirement: 중간 폭 반응형 레이아웃
뷰포트 폭 768px 이상 1024px 미만에서 사이드바는 기본적으로 숨겨지고 토글 버튼으로 여는 오버레이가 되어야 한다(SHALL). 노트 목록과 에디터 영역은 나란히 표시되며, 에디터 영역은 편집/미리보기 탭으로 한 번에 하나만 보여야 한다(SHALL).

#### Scenario: 중간 폭 사이드바 오버레이
- **WHEN** 사용자가 900px 폭에서 사이드바 토글 버튼을 누른다
- **THEN** 사이드바가 그림자 없는 불투명 배경으로 본문 위에 겹쳐 열린다
- **WHEN** 사용자가 닫기 버튼, 오버레이 바깥 영역, 또는 Esc를 누른다
- **THEN** 사이드바가 닫히고 포커스가 토글 버튼으로 돌아간다

#### Scenario: 편집/미리보기 탭 전환
- **WHEN** 900px 폭에서 노트를 선택하고 "미리보기" 탭을 누른다
- **THEN** 원문 영역이 숨겨지고 미리보기만 보이며 "미리보기" 탭이 선택 상태로 표시된다

### Requirement: 좁은 폭 단일 컬럼 레이아웃
뷰포트 폭 768px 미만에서는 노트 목록과 노트 상세 중 하나만 전체 폭으로 표시해야 하며(SHALL), 사이드바는 오버레이, 에디터는 편집/미리보기 탭을 사용해야 한다. 320px 폭과 200% 확대에서 가로 스크롤이나 콘텐츠 잘림이 없어야 한다(MUST).

#### Scenario: 목록에서 상세로, 다시 목록으로
- **WHEN** 사용자가 375px 폭에서 노트 카드를 누른다
- **THEN** 목록이 사라지고 뒤로 가기 버튼, 저장 상태, 편집/미리보기 탭이 있는 노트 상세가 전체 폭으로 보인다
- **WHEN** 사용자가 뒤로 가기 버튼을 누른다
- **THEN** 노트 목록이 다시 보인다

#### Scenario: 최소 폭 리플로우
- **WHEN** 뷰포트 폭이 320px이다
- **THEN** 페이지에 가로 스크롤이 생기지 않고 모든 버튼과 문구가 잘리지 않고 보인다

### Requirement: 인터랙티브 요소의 시각 상태와 접근성
모든 인터랙티브 요소는 키보드로 도달 가능하고 default, hover, focus-visible 상태를 시각적으로 구분해야 한다(SHALL). 목록형 요소(노트 카드, 사이드바 항목, 태그 칩)의 hover/selected/active는 테두리나 그림자 없이 배경색 변화로만 표현해야 한다(MUST). 아이콘만 있는 버튼은 한국어 접근성 이름을 가져야 한다(MUST). 본문 텍스트 대비는 4.5:1 이상이어야 한다(MUST).

#### Scenario: 키보드 탐색
- **WHEN** 사용자가 Tab 키로 화면을 순회한다
- **THEN** 모든 버튼, 카드, 항목, 입력에 포커스 링이 보이고 순서가 시각적 배치(사이드바 → 목록 → 에디터)를 따른다

#### Scenario: 아이콘 버튼 이름
- **WHEN** 스크린 리더가 서식 도구 버튼이나 사이드바 토글 버튼을 읽는다
- **THEN** "굵게", "메뉴 열기" 같은 한국어 이름이 읽힌다

### Requirement: 모션 최소화
상태 전환 애니메이션은 120ms 이하로 제한하고, `prefers-reduced-motion: reduce` 환경에서는 전환 시간이 0이어야 한다(SHALL).

#### Scenario: 모션 감소 설정
- **WHEN** 운영체제에서 동작 줄이기가 켜져 있고 사용자가 사이드바 오버레이를 연다
- **THEN** 오버레이가 애니메이션 없이 즉시 나타난다
