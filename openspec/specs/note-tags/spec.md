# note-tags Specification

## Purpose

노트에 태그를 붙이고 떼어 노트 사이를 잇는 꼬리표로 쓰고, 노트 카드의 태그 칩을 눌러 같은 태그가 붙은 노트만 모아 볼 수 있게 한다. 태그 이름 규칙, 태그 저장, 태그 범위와 그 빈 상태를 정의한다.

## Requirements

### Requirement: 노트의 태그
노트는 태그를 0개 이상 가질 수 있어야 한다(SHALL). 태그는 이름으로만 구별하며 따로 만들거나 지우는 개체가 아니다. 어떤 노트에 붙어 있으면 존재하고, 붙은 노트가 하나도 없으면 존재하지 않는다. 한 노트의 태그는 붙인 순서를 유지해야 한다(SHALL). 사이드바는 태그 목록을 보이지 않는다(`note-ui-skeleton`).

#### Scenario: 마지막 노트에서 떼면 제안에서 사라짐
- **WHEN** "회의" 태그가 노트 A에만 붙어 있고 사용자가 노트 A에서 "회의"를 뗀 뒤 노트 B를 열어 태그 입력창의 제안 목록을 연다
- **THEN** 제안 목록에 "회의"가 없다

#### Scenario: 붙인 순서 유지
- **WHEN** 사용자가 노트 A에 "회의", "할 일", "독서"를 차례로 붙인다
- **THEN** 에디터 태그 줄과 노트 A 카드에 태그가 그 순서로 보인다

### Requirement: 태그 붙이기
노트가 열려 있으면 에디터 상단 줄 아래에 태그 줄이 보여야 한다(SHALL). 태그 줄에는 보이는 "태그" 라벨, 그 노트에 붙은 태그 칩들, 태그 입력창이 있어야 한다(SHALL). 입력창은 늘 보이며 "태그" 접근성 이름을 가져야 한다(MUST). 입력창에서 Enter를 누르면 입력한 이름을 `태그 이름 규칙`에 따라 정리해 그 노트의 태그 끝에 붙이고, 입력창을 비운 채 포커스를 입력창에 두어야 한다(SHALL). 한국어 입력기 조합 중에 누른 Enter는 조합을 끝낼 뿐 태그를 붙이지 않아야 한다(MUST NOT). Enter를 누르지 않은 입력은 태그로 붙지 않는다. 다른 노트를 열면 입력창은 비어 있다. 입력창은 다른 노트에서 쓰고 있고 이 노트에는 아직 없는 태그를 가나다순 제안 목록으로 보여야 한다(SHALL).

#### Scenario: Enter로 태그 붙이기
- **WHEN** 사용자가 노트 A를 열고 태그 입력창에 `회의`를 입력한 뒤 Enter를 누른다
- **THEN** 태그 줄의 입력창 앞에 "회의" 칩이 보이고 입력창은 비어 있으며 포커스가 입력창에 있다
- **AND** 노트 A 카드에 "회의" 칩이 보인다

#### Scenario: 입력기 조합 중 Enter
- **WHEN** 사용자가 태그 입력창에 한국어 입력기로 `회의`를 조합하는 도중 Enter를 누른다
- **THEN** 조합만 끝나고 태그는 붙지 않으며 입력창에 "회의"가 남는다
- **WHEN** 사용자가 Enter를 한 번 더 누른다
- **THEN** "회의" 태그가 붙는다

#### Scenario: 기존 태그 제안
- **WHEN** 노트 B에 "회의"와 "독서"가 붙어 있고, 사용자가 "독서"만 붙은 노트 A를 열어 태그 입력창의 제안 목록을 연다
- **THEN** 제안 목록에 "회의"가 있고 "독서"는 없다

#### Scenario: 붙이지 않은 입력
- **WHEN** 사용자가 노트 A의 태그 입력창에 `회의`를 입력하고 Enter를 누르지 않은 채 노트 B를 연다
- **THEN** 노트 A에 "회의" 태그가 붙지 않았고 노트 B의 태그 입력창은 비어 있다

### Requirement: 태그 이름 규칙
붙일 태그 이름은 입력값에서 앞뒤 공백을 지우고, 그다음 맨 앞의 `#` 문자들과 그 뒤의 공백을 지운 값이어야 한다(SHALL). 이름 안의 공백은 그대로 둔다. 이름의 최대 길이는 두지 않는다. 정리한 이름이 비어 있으면 아무것도 붙이지 않는다. 이름은 대소문자를 구분하지 않고 비교한다. 이 노트에 이미 같은 이름의 태그가 있으면 아무것도 붙이지 않는다. 다른 노트에 같은 이름의 태그가 있으면 그 태그의 철자로 붙여야 한다(SHALL). 두 경우 모두 오류 문구를 보이지 않는다. 긴 이름은 태그 칩, 목록 제목에서 잘리지 않고 줄바꿈되어야 하며, 320px 폭에서도 가로 스크롤을 만들지 않아야 한다(MUST NOT).

#### Scenario: 앞의 #과 공백 제거
- **WHEN** 사용자가 태그 입력창에 `  #할 일 `을 입력하고 Enter를 누른다
- **THEN** "할 일" 태그가 붙는다

#### Scenario: 빈 이름
- **WHEN** 사용자가 태그 입력창에 `#` 또는 공백만 입력하고 Enter를 누른다
- **THEN** 태그가 붙지 않는다

#### Scenario: 이 노트에 이미 있는 태그
- **WHEN** "회의"가 붙은 노트 A의 태그 입력창에 `회의`를 입력하고 Enter를 누른다
- **THEN** 노트 A의 "회의" 칩은 하나뿐이고 입력창은 비어 있다

#### Scenario: 다른 노트의 철자를 따름
- **WHEN** 노트 B에 "React" 태그가 있고 사용자가 노트 A의 태그 입력창에 `react`를 입력하고 Enter를 누른다
- **THEN** 노트 A에 "React" 태그가 붙는다

#### Scenario: 긴 이름
- **WHEN** 320px 폭에서 사용자가 공백 없는 60자 이름의 태그를 붙인다
- **THEN** 태그 칩이 줄바꿈되어 전부 보이고 페이지에 가로 스크롤이 생기지 않는다

### Requirement: 태그 떼기
에디터 태그 줄의 각 태그 칩에는 그 태그를 떼는 버튼이 있어야 하며(SHALL), 이 버튼은 태그 이름을 포함한 한국어 접근성 이름(예: "회의 태그 떼기")을 가져야 한다(MUST). 누르면 그 노트에서 태그를 떼고 포커스를 태그 입력창으로 옮겨야 한다(SHALL). 입력창에서 Backspace를 눌러도 태그를 떼지 않아야 한다(MUST NOT). 에디터 태그 줄의 칩은 누른다고 목록 범위를 바꾸지 않는다.

#### Scenario: 태그 떼기
- **WHEN** 사용자가 노트 A 태그 줄의 "회의" 칩의 떼기 버튼을 누른다
- **THEN** 태그 줄과 노트 A 카드에서 "회의" 칩이 사라지고 포커스가 태그 입력창에 있다

#### Scenario: 빈 입력창에서 Backspace
- **WHEN** 태그가 붙은 노트의 비어 있는 태그 입력창에서 Backspace를 누른다
- **THEN** 태그가 그대로 붙어 있다

### Requirement: 태그 저장
태그를 붙이거나 떼면 `note-persistence`의 즉시 저장 계기와 같이 대기 없이 저장해야 하며(SHALL), 저장 상태 표시는 저장 상태 전이 규칙을 따른다. 태그를 바꿔도 노트의 수정 시각은 바뀌지 않아야 한다(MUST NOT change). 노트의 태그와 그 순서는 새로고침하거나 창을 다시 열어도 그대로 복원되어야 한다(SHALL). 기록 전 새 노트의 태그를 바꾸면 저장소에 기록하지 않는다. 태그 데이터는 노트 저장본 안에만 두며 네트워크 요청을 보내지 않아야 한다(MUST NOT).

#### Scenario: 새로고침 후 태그 유지
- **WHEN** 사용자가 노트 A에 "회의"와 "할 일"을 붙이고 저장 상태가 "저장됨"이 된 뒤 새로고침한다
- **THEN** 노트 A 카드와 에디터 태그 줄에 "회의", "할 일"이 그 순서로 보인다

#### Scenario: 수정 시각 유지
- **WHEN** 어제 마지막으로 고친 노트 A에 태그를 붙인다
- **THEN** 노트 A 카드의 수정 시각 문구는 "어제" 그대로이고 목록에서의 위치도 그대로다

#### Scenario: 기록 전 새 노트에 태그
- **WHEN** 사용자가 "새 노트"를 누르고 원문에 아무것도 입력하지 않은 채 "회의" 태그를 붙인다
- **THEN** 브라우저 저장소에 새 노트 레코드가 없다

### Requirement: 노트 카드의 태그 칩
노트 카드는 그 노트의 태그를 붙인 순서대로 칩으로 보여야 한다(SHALL). 칩은 `#`과 태그 이름으로 보인다. 칩을 누르면 목록 범위가 그 태그로 바뀌고 포커스가 노트 목록 제목으로 가야 한다(SHALL). 칩을 눌러도 그 카드의 노트가 열리거나 선택 노트가 바뀌지 않아야 한다(MUST NOT). 지금 보고 있는 태그 범위와 같은 태그의 칩은 selected로 보이고, 눌러도 아무것도 바뀌지 않는다.

#### Scenario: 칩으로 태그 범위 열기
- **WHEN** 1280px 폭에서 "전체 노트"를 보며 노트 B를 연 상태로 사용자가 노트 A 카드의 "회의" 칩을 누른다
- **THEN** 목록 제목이 "#회의"가 되고 "회의"가 붙은 노트 카드만 보이며 포커스가 목록 제목에 있다
- **AND** 에디터에는 노트 B가 계속 열려 있다

#### Scenario: 보고 있는 태그의 칩
- **WHEN** "#회의" 범위를 보고 있다
- **THEN** 목록의 모든 카드에서 "회의" 칩이 selected로 보이고 다른 태그 칩은 selected가 아니다

### Requirement: 태그 범위
태그 범위는 "전체 노트", "폴더 없음", 폴더와 나란한 목록 범위다. 태그 범위에서는 그 태그가 붙은 노트만 폴더와 관계없이 목록에 보여야 하며(SHALL), 목록 제목은 `#`과 태그 이름이어야 한다(SHALL). 목록의 정렬, 편집 중 위치 고정, 범위를 바꿔도 열린 노트를 닫지 않는 규칙은 `note-folders`의 `범위로 목록 좁히기`와 같다. 태그 범위를 보는 동안 사이드바에는 active 항목이 없어야 한다(SHALL). 태그 범위에서 나가는 전용 버튼은 두지 않으며, 사이드바 범위 항목을 누르면 그 범위로 바뀐다. 열린 노트에서 보고 있는 태그를 떼면 그 카드는 즉시 목록에서 빠지고, 범위와 에디터와 포커스는 그대로다. 새로고침하면 "전체 노트"로 시작한다.

#### Scenario: 폴더와 관계없이 모임
- **WHEN** "회의"가 "업무" 폴더의 노트 2개와 폴더 없음 노트 1개에 붙어 있고 사용자가 "회의" 칩을 누른다
- **THEN** 목록에 세 노트가 최근 수정 순으로 보인다
- **AND** 사이드바에 active 항목이 없다

#### Scenario: 사이드바로 나가기
- **WHEN** "#회의" 범위를 보는 중에 사용자가 사이드바의 "업무"를 누른다
- **THEN** 목록 제목이 "업무"가 되고 "업무" 항목이 active다

#### Scenario: 보는 중에 태그 떼기
- **WHEN** "#회의" 범위를 보는 중에 "회의"가 붙은 노트 A를 열어 "회의"를 뗀다
- **THEN** 목록에서 노트 A 카드가 빠지고 목록 제목은 "#회의" 그대로다
- **AND** 에디터에 노트 A가 계속 열려 있고 포커스는 태그 입력창에 있다

### Requirement: 태그 범위의 빈 상태
태그 범위에 노트가 하나도 없으면(보고 있는 태그를 모든 노트에서 떼거나 그 노트들을 지운 경우) 범위를 바꾸지 않고 목록 영역에 이 태그가 붙은 노트가 없다는 빈 상태를 보여야 한다(SHALL). 이 빈 상태에는 "새 노트" 버튼이 없다. 검색 결과 없음 강제 상태(`?search=empty`)가 켜져 있으면 그 상태가 우선한다.

#### Scenario: 마지막 노트에서 태그를 뗌
- **WHEN** "#회의" 범위를 보는 중에 "회의"가 붙은 유일한 노트 A에서 "회의"를 뗀다
- **THEN** 목록 제목은 "#회의"이고 목록 영역에 이 태그가 붙은 노트가 없다는 문구가 보이며 "새 노트" 버튼은 없다
- **AND** 에디터에 노트 A가 계속 열려 있다

#### Scenario: 마지막 노트를 삭제
- **WHEN** "#회의" 범위를 보는 중에 "회의"가 붙은 유일한 노트를 삭제한다
- **THEN** 목록 영역에 이 태그가 붙은 노트가 없다는 문구가 보이고, 에디터 빈 상태에 "새 노트" 버튼이 보인다

### Requirement: 태그 범위에서 새 노트
태그 범위를 보고 있을 때 만든 새 노트에는 그 태그가 붙어 있어야 하며(SHALL), 폴더는 "폴더 없음"이다. 그 밖의 새 노트 동작은 `note-ui-skeleton`의 `새 노트 만들기`를 따른다.

#### Scenario: 태그 범위에서 새 노트
- **WHEN** 사용자가 "#회의" 범위를 보는 중에 사이드바의 "새 노트"를 누른다
- **THEN** "#회의" 목록 맨 위에 "제목 없음" 카드가 selected로 "회의" 칩과 함께 나타난다
- **AND** 에디터 태그 줄에 "회의" 칩이 있고 폴더 선택에 "폴더 없음"이 보인다

#### Scenario: 입력 후 새로고침
- **WHEN** 사용자가 "#회의" 범위에서 새 노트를 만들어 `# 주간 회의`를 입력하고 1초 기다린 뒤 새로고침한다
- **THEN** "주간 회의" 카드에 "회의" 칩이 보인다
