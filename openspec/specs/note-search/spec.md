# note-search Specification

## Purpose

노트 목록의 검색 입력으로 지금 보고 있는 범위 안에서 내용이 일치하는 노트만 남기고, 왜 일치했는지와 결과가 없을 때 다음에 할 수 있는 일을 목록에서 바로 보여준다.

## Requirements

### Requirement: 검색 대상 텍스트
노트의 검색 대상은 그 노트의 미리보기에 렌더링되어 보이는 글자여야 한다(SHALL). 제목, 문단, 목록 항목, 인용, 표 셀, 인라인 코드와 코드 블록, 링크 텍스트, 이미지 대체 텍스트가 대상에 들어간다. 마크다운 서식 기호, 링크 주소, 이미지 주소는 대상이 아니어야 한다(MUST NOT). 내용이 없는 노트의 대체 제목 "제목 없음"은 대상이 아니다. 태그 이름과 폴더 이름은 대상이 아니다.

#### Scenario: 서식 기호와 링크 주소는 걸리지 않음
- **WHEN** 원문이 `**예산** 확정, [자료](https://example.com/2019)`인 노트 A가 있고, 사용자가 "전체 노트"에서 `예산 확정`을 검색한다
- **THEN** 노트 A 카드가 목록에 보인다
- **WHEN** 사용자가 검색어를 `2019`로 바꾼다
- **THEN** 노트 A 카드는 목록에 없다
- **WHEN** 사용자가 검색어를 `**`로 바꾼다
- **THEN** 노트 A 카드는 목록에 없다

#### Scenario: 표 셀과 이미지 대체 텍스트
- **WHEN** 셀 값이 "분기 매출"인 표와 대체 텍스트가 "조직도"인 이미지가 있는 노트 B가 있고, 사용자가 `분기 매출`을 검색한 뒤 이어서 `조직도`를 검색한다
- **THEN** 두 검색 모두에서 노트 B 카드가 목록에 보인다

#### Scenario: 대체 제목과 태그는 걸리지 않음
- **WHEN** 원문이 빈 노트 C가 "제목 없음" 카드로 보이고 노트 D에는 "회의" 태그가 있지만 원문에 "회의"라는 글자가 없을 때, 사용자가 `제목 없음`을 검색한 뒤 이어서 `회의`를 검색한다
- **THEN** 첫 검색에서 노트 C 카드가 없고, 두 번째 검색에서 노트 D 카드가 없다

### Requirement: 일치 규칙
검색어는 공백으로 나눈 단어의 목록으로 다뤄야 하며(SHALL), 노트는 모든 단어가 검색 대상 텍스트 어딘가에 들어 있을 때만 일치한다. 단어는 텍스트의 일부와 같으면 일치하고, 순서와 인접 여부는 따지지 않는다. 비교는 대소문자를 구분하지 않아야 하며(MUST NOT), 유니코드 정규화 형태(NFC와 NFD)의 차이도 구분하지 않아야 한다(MUST NOT). 공백만 있는 검색어는 검색어가 없는 것과 같다. 입력기로 한글을 조합하는 중에도 입력창에 보이는 값으로 바로 결과를 갱신해야 한다(SHALL). 결과 목록의 순서는 검색하지 않을 때와 같은 최근 수정 순이다.

#### Scenario: 단어별 AND
- **WHEN** 노트 X는 "2019년 3월 회의록", 노트 Y는 "회의록 2019 정리", 노트 Z는 "회의록 초안"을 담고 있을 때 사용자가 `회의록 2019`를 검색한다
- **THEN** 목록에 노트 X와 Y 카드만 보인다

#### Scenario: 부분 일치와 대소문자
- **WHEN** 노트 A에 "React 회의록에서"라는 문장이 있고 사용자가 `react 회의`를 검색한다
- **THEN** 노트 A 카드가 목록에 보인다

#### Scenario: 정규화 형태가 다른 한글
- **WHEN** 노트 A의 원문에 NFD 형태로 저장된 "회의록"이 있고 사용자가 키보드로 `회의록`을 입력한다
- **THEN** 노트 A 카드가 목록에 보인다

#### Scenario: 공백만 입력
- **WHEN** 사용자가 검색 입력에 공백 두 칸만 넣는다
- **THEN** 목록은 검색하지 않을 때와 같다

#### Scenario: 조합 중 갱신
- **WHEN** 사용자가 한글 입력기로 `예산`을 입력하는 중 입력창에 `예`가 보인다
- **THEN** 목록은 이미 `예`로 검색한 결과를 보여준다

### Requirement: 범위 안에서 검색
검색은 목록이 지금 보여주는 범위(전체 노트, 폴더 없음, 폴더, 태그) 안의 노트만 좁혀야 하며(SHALL), 검색어를 입력해도 범위, 목록 제목, 사이드바의 active 항목은 바뀌지 않아야 한다(MUST NOT). 사이드바 항목의 노트 개수는 검색과 관계없이 범위 전체의 개수다.

#### Scenario: 폴더 안에서 검색
- **WHEN** "업무" 폴더의 노트 A와 "개인" 폴더의 노트 B가 모두 "예산"을 담고 있을 때 사용자가 "업무" 범위에서 `예산`을 검색한다
- **THEN** 목록 제목은 "업무"이고 노트 A 카드만 보인다
- **AND** 사이드바의 "업무" 개수와 "전체 노트" 개수는 검색 전과 같다

#### Scenario: 태그 범위 안에서 검색
- **WHEN** 사용자가 "#회의" 범위에서 검색한다
- **THEN** "회의" 태그가 붙은 노트 가운데 일치하는 노트만 보이고 사이드바에 active 항목은 없다

### Requirement: 검색 결과 카드
검색어가 있는 동안 노트 카드는 제목 안의 일치한 부분을 하이라이트해야 한다(SHALL). 스니펫 자리에는 제목을 뺀 본문에서 처음으로 검색 단어가 나오는 줄을, 일치한 부분이 보이도록 앞뒤를 줄여 보여주고, 그 안의 모든 검색 단어 일치 부분을 하이라이트해야 한다(SHALL). 줄인 쪽 끝에는 말줄임표를 붙인다. 본문에 일치가 없으면 검색하지 않을 때의 스니펫을 하이라이트 없이 보여준다. 하이라이트는 약한 강조 배경과 그 짝 글자색을 쓰고, selected 카드 안에서는 캔버스 배경을 써서 카드 배경과 구분되어야 한다(MUST). 하이라이트는 색에만 기대지 않고 배경 면으로 구분되어야 하며, 카드의 접근 가능한 이름은 검색하지 않을 때와 같이 노트 제목이다.

#### Scenario: 본문 깊은 곳의 일치
- **WHEN** 제목이 "3월 회의록"이고 첫 문단이 "참석자: 김, 이, 박"이며 다섯 번째 문단에 "다음 분기 예산은 5% 증액하기로 했다"가 있는 노트 A가 있을 때, 사용자가 `예산`을 검색한다
- **THEN** 노트 A 카드의 스니펫 자리에 "다음 분기 예산은 5% 증액하기로 했다"를 담은 발췌가 보이고 "예산"이 하이라이트되어 있다

#### Scenario: 제목에만 일치
- **WHEN** 제목이 "예산 계획"이고 본문에는 "예산"이 없는 노트 B가 있을 때 사용자가 `예산`을 검색한다
- **THEN** 노트 B 카드의 제목에서 "예산"이 하이라이트되고, 스니펫 자리에는 검색하지 않을 때와 같은 스니펫이 보인다

#### Scenario: selected 카드의 하이라이트
- **WHEN** 사용자가 검색 결과의 노트 카드를 열어 selected로 만든다
- **THEN** 그 카드 안의 하이라이트는 캔버스 배경으로 보여 카드 배경과 구분된다

#### Scenario: 검색어를 지움
- **WHEN** 사용자가 검색 입력의 지우기 버튼을 누른다
- **THEN** 목록은 범위의 모든 노트를 보여주고 카드에는 하이라이트가 없으며 원래 스니펫이 보인다

### Requirement: 검색 결과 없음 빈 상태
범위에 노트가 있고 검색어가 있으며 일치하는 노트가 없으면, 목록 영역에 "일치하는 노트가 없어요" 빈 상태를 보여야 한다(SHALL). 범위에 노트가 하나도 없으면 검색어와 관계없이 그 범위의 빈 상태(`note-ui-skeleton`, `note-folders`, `note-tags`)가 먼저다. 범위가 "전체 노트"가 아니고 전체 노트 가운데 일치하는 노트가 있으면, 빈 상태 설명은 다른 곳에 일치하는 노트가 몇 개 있는지 알려야 하며(SHALL), "전체 노트에서 보기" 1차 버튼을 함께 보여야 한다(SHALL). 그 밖의 경우 설명은 검색어를 줄이거나 다른 단어로 찾아보라고 안내하고 버튼은 없다. 문구에 범위 이름을 넣지 않는다. "전체 노트에서 보기"를 누르면 검색어는 그대로 두고 범위를 "전체 노트"로 바꾸며, 포커스는 목록 제목으로 옮겨야 한다(SHALL).

#### Scenario: 전체 노트에서 결과 없음
- **WHEN** 사용자가 "전체 노트"에서 어떤 노트에도 없는 단어를 검색한다
- **THEN** 목록 영역에 "일치하는 노트가 없어요"와 다른 단어로 찾아보라는 안내가 보이고 버튼은 없다

#### Scenario: 다른 범위에만 결과가 있음
- **WHEN** "업무" 폴더에는 "예산"을 담은 노트가 없고 다른 곳에 3개 있을 때 사용자가 "업무" 범위에서 `예산`을 검색한다
- **THEN** 목록 영역에 "일치하는 노트가 없어요", 다른 곳에 일치하는 노트가 3개 있다는 안내, "전체 노트에서 보기" 버튼이 보인다
- **WHEN** 사용자가 "전체 노트에서 보기"를 누른다
- **THEN** 목록 제목이 "전체 노트"로 바뀌고 검색 입력에는 `예산`이 남아 있으며 일치하는 노트 카드 3개가 보인다
- **AND** 포커스는 목록 제목에 있고 사이드바의 active 항목은 "전체 노트"다

#### Scenario: 빈 폴더에서 검색
- **WHEN** 사용자가 노트가 없는 "보관함" 폴더에서 검색어를 입력한다
- **THEN** 목록 영역에는 검색 결과 없음이 아니라 빈 폴더 상태와 "새 노트" 버튼이 보인다

### Requirement: 열린 노트와 검색어 유지
검색 결과에 없는 노트가 에디터에 열려 있어도 검색 때문에 닫히지 않아야 한다(MUST NOT). 열린 노트를 편집해 일치 여부가 바뀌면 그 카드는 목록에서 빠지거나 다시 나타난다. 검색어는 범위를 바꾸거나(사이드바 항목, 태그 칩, "전체 노트에서 보기") 새 노트를 만들어도 그대로 남아야 한다(SHALL). 검색어는 브라우저 저장소에 쓰지 않으며, 새로고침하면 검색 입력은 비어 있다.

#### Scenario: 열린 노트가 결과에 없음
- **WHEN** "예산"이 없는 노트 A가 에디터에 열려 있고 사용자가 `예산`을 검색한다
- **THEN** 목록에서 노트 A 카드가 빠지지만 에디터에는 노트 A가 계속 열려 있다

#### Scenario: 범위를 바꿔도 검색어 유지
- **WHEN** 사용자가 `예산`을 검색한 상태에서 사이드바의 "개인" 폴더를 고른다
- **THEN** 목록 제목이 "개인"이고 검색 입력에는 `예산`이 남아 있으며 "개인" 안의 일치하는 노트만 보인다

#### Scenario: 새로고침
- **WHEN** 사용자가 검색어를 입력한 뒤 페이지를 새로고침한다
- **THEN** 검색 입력은 비어 있고 목록은 "전체 노트"의 모든 노트를 보여준다

### Requirement: 검색 단축키
모달 다이얼로그(노트 삭제 확인, 폴더 이름 입력 등)가 열려 있지 않으면, 어디에 포커스가 있든 `Cmd+K`(macOS) 또는 `Ctrl+K`(그 밖의 플랫폼)를 누를 때 브라우저 기본 동작 대신 검색 입력에 포커스하고 입력값 전체를 선택해야 한다(SHALL). 모달 다이얼로그가 열려 있으면 이 단축키는 아무것도 하지 않는다. 입력기로 조합하는 중에 누른 `Esc`는 조합 취소로만 쓰이고 검색어를 지우지 않는다. 사이드바 오버레이가 열려 있으면 닫고, 좁은 폭에서 노트 상세가 보이고 있으면 노트 목록으로 돌아간 뒤 포커스한다. 검색 입력에 포커스가 있을 때 `Esc`를 누르면 검색어를 지워야 한다(SHALL).

#### Scenario: 원문 입력 중 단축키
- **WHEN** 1280px 폭에서 사용자가 원문 영역에 글을 쓰다가 `Cmd/Ctrl+K`를 누른다
- **THEN** 검색 입력에 포커스가 가고 기존 검색어가 전체 선택되며 원문에는 글자가 들어가지 않는다

#### Scenario: 좁은 폭에서 단축키
- **WHEN** 375px 폭에서 노트 상세를 보는 중에 `Cmd/Ctrl+K`를 누른다
- **THEN** 노트 목록이 보이고 검색 입력에 포커스가 있다

#### Scenario: Esc로 지우기
- **WHEN** 검색 입력에 `예산`이 있고 포커스가 있을 때 `Esc`를 누른다
- **THEN** 검색 입력이 비고 목록은 범위의 모든 노트를 보여준다

#### Scenario: 모달이 열려 있을 때
- **WHEN** 노트 삭제 확인 다이얼로그가 열린 상태에서 `Cmd/Ctrl+K`를 누른다
- **THEN** 다이얼로그가 그대로 열려 있고 포커스는 다이얼로그 안에 남는다
